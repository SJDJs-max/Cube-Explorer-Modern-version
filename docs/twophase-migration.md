# 常规二阶段求解的源码迁移

此模块迁移 Herbert Kociemba 的 Cube Explorer 5.15 HTM 算法，原始工程保留在 `raw/CubeExplorer-master`，新代码遵循原仓库 GPL-3.0 授权。此文件记录实现对应关系，便于学习和复核。

| 原始源码 | 新版实现 |
|---|---|
| `CubeDefs.pas`：角棱乘法、六面转动、对称生成元 | `model.cpp` 的物理动作；`twophase.cpp` 的内部反射对称乘法 |
| `CubiCube.pas`：CornOri、EdgeOri、UDSlice、CornPerm、Phase2EdgePerm | 同名含义的整数坐标函数，保留原混合进制排列编号 |
| `Symmetries.pas`：F2/U4/LR 的 16 个保持 UD 轴的对称 | `build_symmetries`，顺序保持一致 |
| `CordCube.pas`：转移表、共轭表、GetPacked | `Tables` 的不可变查找表与 `packed_value` |
| `Search.pas`：Next2PhaseSolution / NextPhase2ID | `Search::phase1` / `Search::phase2`，明确参数与递归回溯替代标签跳转 |
| `TripSearch.pas`：TripleSearch / S_URF3 | `use_triple_search`：UD、RL、FB 三轴并发，共享最佳长度、总预算与取消 |

## 保留的数学结构

第一阶段使用角块朝向（2187）与翻棱/中层位置的 64430 个对称类；进入子群 `G1=<U,D,R2,L2,F2,B2>` 后，第二阶段使用角排列（40320）、UD 层棱排列（40320）和中层棱排列（24）。第二阶段剪枝表对角排列使用 2768 个对称类。

原剪枝距离以模 3 形式存储，每字节五项。原文件采用四项连续加第五项分区的布局，新代码按完全相同规则读取。源代码中的 x86 汇编被显式无符号整数索引替代，未改变压缩数据含义。

进程首次加载会读取四份原始表，验证文件长度和固定 FNV-1a 指纹，然后在内存中生成小型坐标转移和共轭表。当前实现按规范化表目录保留进程期只读缓存，独立创建的 GUI 搜索对象和同时到达的请求也共享同一份表，最后一个临时搜索对象销毁后不会卸载。该指纹用于损坏/版本检查，并非安全签名。每次求解的路径、统计和取消状态彼此独立，准备及等待共享表的阶段也接受取消标记。不同表目录各自验证和缓存；进程内已加载的表不会自动随磁盘文件改变。

`Search.pas:747` 的策略被保留：第一阶段路径如果已经进入 G1，就不继续延长这个第一阶段前缀。这使常规二阶段搜索很快，但不能用于证明全局最优。结果中的 `optimality_proven` 因此保持 false。

普通搜索也恢复原 `Next2PhaseSolution` 的同轴幂次剪枝：若某幂次的下界比当前剩余深度还大，其余幂次最多改善一步，整轴均可跳过。角坐标和进入 G1 后的块状态按原 `inValid` 思路只重算回溯改变的路径后缀；模三距离更新使用原 `GetPruningLength` 型查表。它们改变实际搜索工作量，不改输出公式、转动数或验证过程。

`use_triple_search=false` 沿用原 `Options.pas` 默认值。开启后使用原 `S_URF3` 共轭得到三套普通二阶段搜索，候选映射回输入的实际朝向并再次独立验证。三轴共享总 `node_limit` 和 `time_limit`，不把预算乘三；不限节点时分轴计数，避免每节点争用一个原子计数器。候选回调串行执行且严格改进，全局取消保留已经发布的最佳候选。`search_axes` 为 1 或 3；每条公式的 `search_axis` 为 0=UD、1=RL、2=FB，表示输入逻辑中心参考系中的第二阶段轴。并行搜索的先后次序可能改变具体公式，但实际动作、相位长度、步数和复原验证始终一致。

## 明确的边界

此接口执行 HTM 下的 18 种普通面转，并精确复原普通三阶魔方，不接受宽转、模 U 或公式枚举规则。半转算一步。输入可以有空间朝向，搜索在规范中心参考系中进行，返回动作映射到输入的实际朝向。

彩色中心方向复原及原常规 slice-mode 尚不在此接口中启用；中心方向状态随回放保留，但普通复原条件不约束其方向。UI/API 必须把特殊中心约束路由到公式求解，不能接受后默默丢弃。不能把当前接口描述为“已迁移所有原 GUI 功能”。公式求解的中层、宽转和转体由独立模块负责。

## 输出与验证

结果计步直接来自搜索路径长度，phase1/phase2 长度相加等于转动步数。每次产生更短候选时，先进行 cubie 回放，再由独立的 54 面片几何模拟器验证同一动作序列。验证失败会抛出错误，不会将公式报告为成功。

取消、时间限制、节点限制和深度限制分别报告；若限制发生前已找到公式，保留已经验证的最佳结果，同时记录实际停止原因。达到 target_moves 仅表示达到请求阈值，不代表全局最优。

## 回归测试

`tests/twophase_tests.cpp` 覆盖零步状态、全部 18 个一步状态、非默认朝向、非法翻棱、准备/搜索取消、首次候选之后取消、时间/节点/深度限制，以及八个并发请求共享表。随机测试交替使用 25 步打乱与直接生成的合法角棱排列/朝向状态。所有求解结果均独立回放验证。

测试程序参数为 `[样本数] [可选TSV输出文件] [可选目标步数] [可选三轴0/1]`。使用 steady_clock 纳秒精度对每次 solve 调用计时，并累加原始时长；另测整批 wallclock，不以每项已取整的毫秒之和计算性能。三轴额外覆盖全部 24 个输入朝向、第二阶段后缀所属轴、精确共享节点预算、总时限、首次候选取消及八项并发。

2026-11-12，在当前机器 GCC 15.1、`-O3` 构建的 500 例回归中，全部结果不超过 21 步；总访问节点 8,895,256，solve 调用的高精度累计 256.141 ms，含输入生成、复验和日志的批次 261.584 ms。表初始化含文件指纹检查 137 ms，计算的表驻留空间 66,240,806 字节。这是当前机器和固定测试数据的实测记录，不是对任意输入的速度保证，也不是与原版的内核速度对比。

## 0.3 性能修复的可复现实测

以下基线是**本轮修改前的新版 C++ 实现，不是原版 Delphi EXE**。同一机器、`-O3 -DNDEBUG`、固定种子 `0x5cfee229`、500 个交替打乱/直接合法状态、目标 **20 步**、每项 3 秒预算。与上一节历史的 21 步目标不同，不能混用两组时间计算倍率。

| 实现 | solve 累计 | 中位数 | P95 | 最慢项 | 节点总数 |
|---|---:|---:|---:|---:|---:|
| 本轮修改前新版，单轴 | 10722.181 ms | 1.311 ms | 85.883 ms | 498.922 ms | 546501361 |
| 修复后单轴 | 7672.685 ms | 1.033 ms | 63.326 ms | 366.402 ms | 282241924 |
| 修复后可选三轴 | 652.713 ms | 0.306 ms | 4.505 ms | 50.149 ms | 48967242 |

三组各 500 项均得到不超过 20 步的实际公式并通过独立几何回放。单轴修复前后 500 条输入和公式逐条相同；三轴候选由真实并行搜索决定。本机这批数据的三轴收益明显，但简单输入的线程启动成本和其他机器的调度可能改变收益，不能据此保证任意情况都更快。

GUI 延迟的主要额外原因是每条结果开始搜索时重新构造 `TwoPhaseSolver`：修复前六次顺序构造均重复读取、校验及建表，每次约 136.8–139.8 ms；修复后首次 141.5 ms，后续五次 0.043–0.101 ms，随后 solve 不再承担重新建表。表驻留空间仍为 66240806 字节。独立回放验证 10000 次约 24 ms，不是该延迟的主要来源，未削弱或关闭验证。

逐项输入/公式/节点/微秒数据在 `bench/twophase-v4/{baseline-500,final-single-500,final-triple-500}.tsv`；运行日志在 `logs/twophase-{baseline,final-single,final-triple}-v4.txt`，构造计时在 `logs/twophase-startup-{baseline,optimized}-v4.txt`。冻结的旧新版测试程序为 `bench/twophase-v4/baseline-tests.exe`，新程序为 `bench/twophase-v4/final-tests.exe`，都只位于新工作区。

## 0.3.1 的源码核对与性能验证

本轮只保留两项有明确依据的修改，使用相同四份原表，不增加下载或表容量：

1. 补齐 `Search.pas:1163` 的阶段二同面幂次剪枝。对于 U/D，若一个幂次的下界比子节点剩余深度多出至少两步，其余幂次最多改善一步，因此整面后续幂次均可跳过。循环保持原 `U U2 U' R2 F2 D D2 D' L2 B2` 顺序。R/F/L/B 在阶段二只有半转，不引入其他动作。
2. 限制阶段二根下界的还原工作。原 `CordCube.pas:GetPrunPhase2` 从模三表一直下降到投影原点，得到精确距离。新版需要先判定该前缀能否改善已有公式：将已有角排列下界向上取整到符合当前模三余数的距离，再加已下降的步数；一旦这个可采纳下界超过可用阶段二步数，直接判定前缀不可行。只有仍可能改善时才继续求精确距离。下降一步时复用已知子余数，避免再次读取同一投影。允许长度不小于投影直径 18 时跳过额外角下界检查。它改变计算工作量，不改变可行目标、候选顺序或公式长度。

调查阶段的 100 个固定输入产生 83,100,737 个阶段一节点、298,306 个阶段二节点，但有 2,669,445 个 G1 终点和 518,835 次阶段二根距离还原。由此优先减少根下界评估成本，未加入收益不足以证明的额外大型剪枝表。搜索节点计数不包含下界还原内部的投影下降操作，因此节点数的小幅变化不代表 CPU 工作量只减少同样比例。

以下比较为 **冻结的新版 C++ 0.3 与 C++ 0.3.1，不是 Delphi 原版实测**。同一机器、GCC 15.1、`-O3 -DNDEBUG`、种子 `0x5cfee229`，每组 500 个混合打乱/均匀合法状态，目标 20 步、每项 3 秒；依次交替运行三组。累计时间列取三组累计时间的中位数，单项中位数/P95 汇总各实现的 1500 次调用，均排除首次加载原表的时间。

| 搜索 | 实现 | 500 项累计中位数 | 单项中位数 | 单项 P95 | 累计时间减少 |
|---|---|---:|---:|---:|---:|
| 单轴 | 0.3 | 7860.486 ms | 1.0763 ms | 66.2231 ms | — |
| 单轴 | 0.3.1 | 6025.074 ms | 0.7496 ms | 49.5971 ms | 23.35% |
| 三轴 | 0.3 | 622.220 ms | 0.28565 ms | 4.3882 ms | — |
| 三轴 | 0.3.1 | 475.257 ms | 0.2482 ms | 3.2216 ms | 23.62% |

单轴每组节点从 282,241,924 降为 281,886,302，1500 对输入的**每一条首候选、中间候选和最终公式均逐字相同**。三轴仍由真实并行调度决定候选，所有结果均不超过 20 步并通过独立几何回放。全部候选严格变短，算法步数及两阶段长度保持一致；不是在显示后删改公式。

首候选单轴中位时间为 0.0198→0.0214 ms，三轴为 0.0668→0.0654 ms。主要收益在找到候选后继续搜索到 20 步，不能把累计搜索收益描述为首次显示候选也同幅加快。首次建表约 140 ms，后续实例继续复用常驻表；驻留空间仍为 66,240,806 字节。额外测得 20 动作的独立几何验证执行 10000 次约 40.695 ms，普通搜索保留每个成功候选的全部独立验证。

回归增加直接进入 G1 的中层三循环及 24 个随机子群输入，防止仅复原角/UD 棱就误判整体复原；单轴/三轴分别验证 2、31、1024、10000 的共享节点预算不被乘三或超额。同时继续覆盖 24 个输入朝向、首候选之后取消、超时、并发以及表缓存。

冻结基线源码和前后测试程序在 `bench/twophase-v031`，`summarize.py` 逐项核对输入及单轴完整候选序列，并产生含 SHA256 的 `summary.json`。逐项结果为 `{baseline,final}-{single,triple}-run{1,2,3}.tsv`，原始日志为 `logs/twophase-v031-*.txt`；构造/验证计时为 `logs/twophase-v031-startup-verification.txt`。没有再次尝试执行此前被策略拒绝的原 EXE。

## 原版速度对照的限制

原 `TcpServer.pas:241` 起，每次 HTTP 求解结果回收至少等待 `Sleep(300)`，内部 QueryPerformanceCounter 计时代码被注释。因此 HTTP 延迟包含固定轮询开销，不能直接用于比较搜索内核。尝试在独立的新工作目录隐藏启动原版 5.14 来测同批输入时，执行工具的自动审批策略拒绝了该动作（`blocked by policy`）；命令未执行，未启动原版进程。未完成原版性能测量，不据此宣称新旧内核有任何倍率的提升。
