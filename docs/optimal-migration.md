# 原版标准最优求解迁移

主界面的“最优”复选框选择实际搜索器；它不是公式已经最优的标志。运行箭头开始 / 停止当前结果行的搜索。原版 `RubikMain.pas:1515–1640`、`OptSearch.pas:37–86` 使用这一交互。最优性必须由算法证明，不能用普通二阶段返回候选替代。

## 算法对应

`src/core/optimal.cpp` 迁移原版标准 HTM 最优搜索的基本结构：

- `Search.pas:175–686`：18 个外层转动上的迭代加深 IDA*，逐个增加步数预算。
- `Search.pas:448–458`：在 UD、RL、FB 三个方向使用原版 phase-one PDB，取最大下界。
- `CubeDefs.pas:266–267,305–306`：原始 `S_URF3`，循环变换三个方向；构造时验证其三阶性质以及对全部 18 个面转的映射。
- `Search.pas:470–478`：三个正下界相同时再加一。理由是任何复原公式的最后一转属于至少一个方向的目标子群，所以该方向应能在总长度减一以内进入子群；三个下界均为 d 时，长度 d 不可能复原。

二阶段模块只新增 `Phase1Cursor`、`phase1_cursor` 和 `advance_phase1` 的只读接口。原普通 `solve`、G1 前缀规则和输出均不改。最优模块不使用普通二阶段的 G1 前缀截断，因此不会丢失离开 G1 后取得更短结果的路径。

搜索热循环通过原有转移表更新压缩坐标，再按模 3 距离恢复相邻层的实际下界，无需每个节点重新解码整个原始距离。所有动作都保持标准外层 HTM；宽转、模 U 和公式枚举限制不进入此搜索器。中心方向等特殊约束仍使用公式模式。

没有下载 Huge / Ultra Huge 求解器大表，也没有声称迁移其额外加速或原版全部对称前缀优化。已保留安全的同面合并和相对面交换顺序剪枝。完整随机魔方的最优性证明仍可能耗时很长，必须支持取消并显示未完成状态。

## 上界、下一公式与证明标志

`OptimalOptions.initial_solution` 可传入先前普通二阶段得到的候选。该候选在使用前会检查动作集合、精确复原和独立几何回放。穷尽全部更短长度后，下界与候选长度相遇，即可证明它最优。

超时、节点预算或取消会保留尚未排除的合法候选，返回 `solved=true`、`optimality_proven=false`。界面必须分别看这两个字段：合法公式不等于已经证明最优。

`excluded_solutions` 接受同一输入已经展示过的标准公式字符串，供原版“下一公式”操作使用。搜索不会把被排除的目标误认为无解；它仍记录已存在的最短目标长度。若下一条公式比已知最短长，则 `optimality_proven=false`。每次调用重新遍历到下一未显示公式，当前实现不序列化旧递归栈；取消后仍可再次搜索。

`OptimalProgress` 报告当前深度、已完整搜完的深度、节点与耗时。`found / time_limit / node_limit / cancelled / depth_limit / invalid_input` 分别报告。`max_moves` 允许 0..60；时间 0 与节点 0 表示相应预算不限。

## 实际验证

`tests/optimal_tests.cpp` 已通过 55,488 项检查：

- 不使用 PDB 或动作剪枝的 BFS 穷举全部 46,741 个不超过四步的状态，逐个证明三轴下界没有高估真实距离。
- 全部两步以内状态及三、四步抽样，最优搜索返回长度等于独立 BFS 真距离，输出做几何回放。
- 3,000 次随机动作的增量 cursor 距离与完整 PDB 重新求距一致。
- 24 个输入握持朝向均返回正确、等长的物理公式。
- 下一公式、错误候选、初始上界、上界保留但未证明、预算、预取消及运行中取消均有验证。

当前机器 Release 实测：3、6、7、10 步示例均在毫秒计时分辨率内完成；一个 14 步示例经 28,615 节点、32 ms 证明最优。一个 20 动作打乱示例在 1,500 ms 预算耗尽时，仅完成至 15 层；保留 20 步普通候选，明确 `optimality_proven=false`。实际输出在 `logs/optimal-v2-bench.txt`。这些是有限样例，不能推断所有输入速度，也没有完成与原 EXE 的同机速度比较。
